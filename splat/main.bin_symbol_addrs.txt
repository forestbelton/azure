// Hand-maintained symbol declarations for main.bin. The yaml has pointed
// `symbol_addrs_path` here from the start.
//
// NOTHING IN HERE IS LOAD-BEARING ANY MORE, measured 2026-11-09 by emptying
// the file: splat re-splits and all four containers still come out
// byte-identical. It is kept for the record, because the one entry below was
// load-bearing for a day and the reason is worth keeping.
//
// Why it stopped mattering: the 0x80020000 overlay's text is a `c` subsegment,
// so splat disassembles no functions in that segment, so rodata migration has
// nothing to attribute a symbol to and emits nothing at all. Symbol names and
// sizes only steer output that is no longer produced. csrc/ovl_main_80020000.c
// defines all 2340 bytes of that .rodata itself.
//
// D_800200B8 -- SPLITTING ONE RODATA OBJECT IN TWO.
//
// While the text was `asm`, spimdisasm found a single reference to
// 0x800200B8, from set_save_icon, and so emitted 0x800200B8..0x80020924 as ONE
// 0x86C-byte `dlabel`. It is really two things:
//
//   * 0x800200B8, eight bytes, a GPU `RECT` {x=0x380, y=0x100, w=4, h=0x10}.
//     set_save_icon copies it onto its stack as
//     `*(RECT *)SAVE_ICON_VRAM_RECT` and walks it across three StoreImage
//     calls, so the type is witnessed, not
//     guessed. It is `const RECT SAVE_ICON_VRAM_RECT` in the C unit now.
//   * 0x800200C0, the rest, the overlay's 59 Shift-JIS UI messages. These no
//     longer have symbols OR an assembly file: they are the string literals
//     of the eight `u8 *` tables in the C unit's .data, and cc1psx emits them
//     at these addresses by itself. docs/owning-data.md §4.7 has the rule and
//     the measurement.
//
// Giving the first a `size` is what made spimdisasm end the object there, and
// the split alone was not enough -- nothing referenced the pool, and migration
// only emits what it can attribute to a function, so the split created the
// symbol and wrote the data nowhere. That trap is docs/owning-data.md §4.6; it
// is how the `hrodata` subsegment came to exist, and §4.7 is how it went away.
D_800200B8 = 0x800200B8; // size:0x8

// D_800887F4 -- THE MENU STRING POOL, which needs a symbol to exist at all.
// Nothing in any text references it: the pointer table in this overlay's
// .data points at it as raw `.word` literals, so spimdisasm has no reference
// to infer a symbol from and the undotted `ovl_main_80088760_str` subsegment
// came out holding only D_800888AC. Declaring the start is what makes the
// 0xB8 bytes of Shift-JIS/ASCII menu text disassemble into that object.
D_800887F4 = 0x800887F4; // rodata

// D_80400714 -- ENDING A LABEL THAT SPLAT CUT INSIDE AN OBJECT, and this one
// IS load-bearing: without it the link fails.
//
// The twin's rodata is owned per translation unit as of 2026-11-13 -- this
// chunk by csrc/main/debug/cardbk.c -- and 0x80400714 is ONE eight-byte object
// there: 82 A0 82 C6 00, two Shift-JIS characters and a terminator, then
// padding. func_804053A0 copies five bytes of it with a block move, which
// comes out `lw D_80400714` + `lb` at +4, so spimdisasm named the byte load's
// target and emitted a second label, D_80400718. That label used to be defined
// by the generated rodata_post listing; with the chunk owned, nothing defines
// it, and while func_804053A0 was parked its nonmatching listing failed to
// link against it.
//
// func_804053A0 LANDED 2026-11-13, so no listing is compiled from it any more
// and this entry is no longer load-bearing for the link. KEEP IT: `make splat`
// still regenerates that listing, and the size is what stops spimdisasm
// inventing the name a second time.
//
// A `size` is what tells spimdisasm the second address is inside the first, so
// it spells the relocation `%lo(D_80400714 + 4)` instead of inventing a name.
// docs/owning-data.md §4.6 is the technique and §9.5 called this the
// landing-time chore; this is it. The same shape at 0x804006C2, inside
// D_804006C0, needs no entry: func_80404EA0 is compiled C, so there is no
// listing to relocate, and the only trace left is a harmless absolute
// assignment in main.bin_undefined_syms_auto.txt.
D_80400714 = 0x80400714; // size:0x8
