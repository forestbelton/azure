# The monster/spell/character string pool from main.bin: 134 strings in
# full-width Shift-JIS, each NUL-terminated and padded with zeros to the next
# 4-byte boundary, which is the default entry form below.
#
# Covers rom 0x020800..0x021268.
#
# Full-width is how the US release renders Latin text in the Japanese font:
# 0x8260-0x8279 are A-Z, 0x8281-0x829A are a-z, 0x8140 is space, 0x8144 a
# period. One entry, U-BOAT, spells its dash with 0x817C, a full-width MINUS
# SIGN (U+2212) rather than a hyphen; all 134 strings were checked to
# round-trip through the encoder before this file was written.
#
# WHAT IT IS. From the AZURE_EGG entry on, the pool runs in groups of three: an
# egg description, the monster NAME in capitals, then a colour in lower case.
# The grouping is not rigid -- BLOCK and METAL share the one "sky blue" that
# follows them, and so do UNICORN/UNIVERN, CLOWN/DEATH, NYUEL/BATTNEL,
# ARACHNE/ASHRA, SNOWMAN/SABER, GRIFFON/GRINEUT, FLAME/IFRIT and DRAGON/KEWNE.
# The eleven entries before AZURE_EGG are not in the pattern at all: four
# character names (Beldo, Selfi, Ghosh, Guy), the three wall spells, Salaman,
# FROG, and two colours.
#
# THE LAST ENTRY'S PADDING IS NOT ZEROS, which is why ULTIMATE is the one entry
# written as a pair of lines. "Ultimate" ends with its NUL at 0x21264, and
# 0x21265..0x21268 is C4 0D 0E -- the original toolchain's buffer showing
# through where it padded the pool up to the 4-aligned table that follows. It
# is the fifth instance of that in the project and the first found outside a
# rodata/text boundary; docs/owning-data.md 4.8 has the other four. So the
# string takes `:nopad=`, which stops the generator computing a zero pad, and
# the three bytes follow as a `:bytes=` line under no label of their own.
#
# HOW IT WAS BUILT. One `hrodata` subsegment replaced 17 one-string `shiftjis`
# segments covering 0x20800..0x20940 plus the 2,368-byte
# `[0x20940, bin, str/main/pool_tail]` after them -- 18 segment blocks in the
# linker script for 2.6 KB of text, two thirds of it never decoded. Sixteen of
# the 17 old symbol names come out of the rule below unchanged. The seventeenth
# was WRONG, and is corrected here: the old
# `[0x20904, shiftjis, str/main/cinnabar]` spanned 32 bytes, which is TWO
# strings, and put STR_MAIN_CINNABAR on the first of them. 0x20904 is GOLEM and
# 0x20910 is cinnabar; each has its own label now.
#
# Names are "NFKC to ASCII, strip a leading `A `/`An ` and a trailing ` egg.`
# down to `<NAME>_EGG`, non-alphanumerics to `_`, upper case". To regenerate
# the bytes from the ROM rather than editing by hand, the walk is: split on the
# first NUL, then expect the next entry at the next 4-aligned offset.
